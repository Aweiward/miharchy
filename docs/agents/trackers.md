# Trackers

Tracker login, tracking panel and when progress reaches a tracker.

- Trackers (`window/Trackers.js`) are miharchy-core's (#371, `core/README.md`): core stores every tracker token, the window stores no credential. Settings lists every tracker `tracker.list` offers. An OAuth tracker (one with an `authUrl`) opens the user's browser with `xdg-open`; the provider ends on `https://suwayomi.org/tracker-oauth` with the token or code in the address, and the user pastes that address into Miharchy, which hands it to `tracker.login { trackerId, callbackUrl }`. Kitsu and MangaUpdates take a username and password instead (`tracker.login { trackerId, username, password }`). Core keeps one MyAnimeList or MangaBaka link until the login ends, so the login asks for its link at Enter; a failed MAL or MangaBaka login discards the link, and Esc and Enter fetch a fresh one. A refused login is core's `invalid` error, whose message already names the tracker.
- A `chapter.update` does not push to trackers. The reader sends `track.progress` after the save that first marks a chapter read (setting `trackAfterReading`, Mihon's `autoUpdateTrack`), and `shell.qml` `markChapters()` after a mark read (`window/Chapters.js`, the chapter actions every view shares) as setting `trackOnMarkRead` says (Mihon's `autoUpdateTrackOnMarkRead`): always, never, or ask (`root.trackAsk`, scope `track-ask`: y pushes, n or Esc keeps), asked only when a logged-in tracker sits below the manga's highest read chapter; the server then sends each track the highest read chapter number, only when it is above the tracker's. `track.bind` pushes it too. Updates acts on chapters of many manga through the same `markChapters(chapters, action, mangaIds)`: it pushes each manga once, and only an open manga detail whose manga is in `mangaIds` hears the reply. Its selection is a set of chapter ids (Mihon inverts it), not the manga detail's `v` range. `t` on a manga opens its tracking panel (`TrackPanel.qml`): Enter finds the manga, `s` status, `c` chapters read, `S` score, `d`/`D` the start and finish dates (typed as YYYY-MM-DD, saved as UTC midnight milliseconds, empty clears; only where the tracker `supportsReadingDates`), `p` private (where it `supportsPrivateTracking`), `o` opens and `y` copies the track's `remoteUrl`, `x` stops tracking. Every change is a `track.update`, which calls the tracker, so it needs the login.
- `docs/spikes/tracker-recommendations.md` tests AniList recommendations found through global search, with no tracker login.
