# Trackers

Tracker login, tracking panel and when progress reaches a tracker.

- Trackers (`window/Trackers.js`) are Suwayomi's: the server stores every tracker token, Miharchy stores no credential. Settings lists every tracker the server offers. An OAuth tracker (one with an `authUrl`) opens the user's browser with `xdg-open`; the provider ends on `https://suwayomi.org/tracker-oauth` with the token or code in the address, and the user pastes that address into Miharchy, which hands it to `loginTrackerOAuth`. Kitsu and MangaUpdates take a username and password instead (`loginTrackerCredentials`). Every read of a logged-out tracker builds a new `authUrl`, and MyAnimeList's carries a new PKCE verifier that replaces the last one, so the login asks for its link at Enter and nothing reads the trackers until it ends.
- The GraphQL `updateChapter` does not push to trackers (only Suwayomi's REST call does). The reader sends `trackProgress` after the save that first marks a chapter read (setting `trackAfterReading`, Mihon's `autoUpdateTrack`), and `shell.qml` `markChapters()` after a mark read (`window/Chapters.js`, the chapter actions every view shares) as setting `trackOnMarkRead` says (Mihon's `autoUpdateTrackOnMarkRead`): always, never, or ask (`root.trackAsk`, scope `track-ask`: y pushes, n or Esc keeps), asked only when a logged-in tracker sits below the manga's highest read chapter; the server then sends each track the highest read chapter number, only when it is above the tracker's. `bindTrack` pushes it too. Updates acts on chapters of many manga through the same `markChapters(chapters, action, mangaIds)`: it pushes each manga once, and only an open manga detail whose manga is in `mangaIds` hears the reply. Its selection is a set of chapter ids (Mihon inverts it), not the manga detail's `v` range. `t` on a manga opens its tracking panel (`TrackPanel.qml`): Enter finds the manga, `s` status, `c` chapters read, `S` score, `d`/`D` the start and finish dates (typed as YYYY-MM-DD, saved as UTC midnight milliseconds, empty clears; only where the tracker `supportsReadingDates`), `p` private (where it `supportsPrivateTracking`), `o` opens and `y` copies the track's `remoteUrl`, `x` stops tracking. Every change is an `updateTrack`, which calls the tracker, so it needs the login.
