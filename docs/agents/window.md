# Window

Conventions that hold across the views in `window/`: restart, mouse, Settings, modes, preferences, the reader's chapter list.

- miharchy-core is the only server (ADR 0010, #373). `shell.qml` reads `core.json` (`MIHARCHY_CORE_CONFIG`, default `~/.config/miharchy/core.json`) into `config`, `{ url, secret }` from `Model.parseCoreConfig`, and passes it to every view. The config waits for the runtime folder check (`heldConfig`). Suwayomi's `server.json` (`suwayomiConfigPath`) is read only by Setup's probe and move. A payload is `{ route, body? }`, sent by `Session.send` as `POST /api/<route>` with the secret as the bearer token, and read by `Model.coreReply`, which gives the connection states and core's error `kind`. `Session.send` refuses a payload with no `route` and logs `miharchy: refused …`, since some sends drop their reply; a drive greps `window.log` for it and must find none. `Model.problem(state, path)` words the failures. `connection` is the library (`library.list`): `fetchLibrary()` refreshes it, and `Model.fromResponse` reads it into manga and categories. A launcher target with or without a trailing `core` (`open-chapter`, `peek-open`, IPC `openChapterOn`, `peekOpenOn`, `MIHARCHY_OPEN_CHAPTER`, `MIHARCHY_PEEK`) holds core's ids; a pending one waits for the config (`targetReady`, `applyPending`). `Widgets` parses the host's filter and setting JSON (`type`, `state`, settings by `key`, an `info` type shown as a header), and `filterChanges` sends every filter's state, which the host copies over a fresh list by position; `listing.filterCount` keeps the count of changed filters. `PrefStore` and `Prefs.js` keep global choices in global metas, and a manga's own choices load with the global ones through `meta.get`'s `queries`, the manga's winning by `scope`. The library check builds its data from `library.list`, the source names meta, `extension.list`, `update.status` and `settings.get` (`LibraryCheck.load`), and the merge prompt's from `manga.get`, `track.list`, `tracker.list` and `category.list` (`mergeLoad`); a dismiss is one `meta.set`. Migrate's loads and writes (`Migrate.libraryLoad`, `highestLoad`, `oldLoad`, `targetLoad`, `writeTarget`, `writeOld`) use `library.list`, `chapter.list`, `manga.get`, `manga.refresh`, `track.list` and `tracker.list`. The target's write adds it to the library last (`manga.update`), so a stop midway leaves no second copy there; a track moves with `track.bind { mangaId, recordId }`. The download routes answer with the plain status `{ state, queue }` (`Downloads.statusIn`), each item with its `error { kind, message }` (`Failure.coreReason`), and the `downloads` topic sends that whole status on each change. `LiveSocket` takes a `topic` and opens `/api/live` with no subprotocol and the secret as its first message (`Live.coreOpen`, `Live.parseCore`). Core has no `FINISHED`: a chapter that leaves the queue settles by `chapter.list { ids }` (`NextChapters.settleLoad`), and delete after read reads `chapter.list` and `library.list`'s category metas (`Downloads.autoDeleteLoad`). A list that crossed a QML `signal (var)` is no JS array, so these checks test for the field, never `Array.isArray`. Up next (`UpNext.load`) reads `library.list`, `chapter.list` and `meta.get`, and a peek opens the reader through `openOn`. The reading card pages `history.list` (`readOnly`) by offset. History loads the cleared cutoff from `meta.get` and the newest 500 from `history.list` (`History.load`), and hides and clears through `meta.set`. The default category setting holds a category id, which `addedToLibrary` applies. Updates reads `library.list`, `chapter.list`, `update.status` and the skip filters' global metas (`Updates.load`), starts and stops runs with `update.start` and `update.stop`, and follows the `updates` topic; its status is flat and says `stopped`, which can come before the stop's reply (`Updates.reduce` "live"). Settings: `loadSettings()` sends `Settings.loadPayloads()` (`settings.get`, then a global `meta.get`) one after the other. Server rows save with `settings.set` and meta rows with `meta.set`. `settingsState.unapplied` names the rows core stores but does not use, and a save core refuses as `invalid` shows under its row (`settingsRefusal`). The tracker rows, storage (`storage.get`, `cache.clear`) and Create a backup use the same config. Setup (`Setup.STEPS`): `coreBuild` (a copy of `core/` and `sync/`, fingerprinted by `CORE_FINGERPRINT`), `coreService` (the unit, then `core.json`), `move` (`move.start`, then `move.status` each second; a done move only checks again) and `suwayomiOff`; FlareSolverr shows "not on core" (#361). A mark read pushes with `track.progress` (`Chapters.trackPayload`) or asks after `Chapters.trackCheckLoad` (`tracker.list`, `track.list`, `chapter.list`), and the tracking panel loads through `Trackers.panelLoad` (`tracker.list`, `track.list`).
- The window never reloads its code in place (`settings.watchFiles: false` in `shell.qml`): Quickshell's reload would catch an update half written and drop the reader without its save. Every 30 s it fingerprints its own `*.qml` and `*.js` (`window/Restart.js`, read only); when the files differ from what it loaded, the status bar shows "new version   Q restart". `Q` (`window.restart`, also the palette and a click) starts a detached sh that waits for this pid to end, unsets `MIHARCHY_OPEN_CHAPTER` and `MIHARCHY_OPEN_VIEW`, and runs the launcher, then runs the quit path (`reader.quit()`).
- A child process whose output the window or the mark reads runs through `Capped.command(argv, cap, seconds)`: a deadline (`timeout`, which kills the process group) and its stdout cut to `cap + 1` bytes by `head -c`. Its parser treats output over `cap` as an error (`Capped.over`, which counts UTF-8 bytes). The command builder and the parser sit in the same JS module and share the cap: `Setup.LIMITS` holds one per Setup job, `Setup.parseJob(text, cap)` fails a job over its cap or with no status line, and `Images.sweep` removes nothing unless the listing ends in `end`. Data reaches an `sh -c` script only as positional arguments. The restore (`Restore.command`) streams its lines and is not capped yet.
- The window writes its runtime files (server images, the reading card, Setup's QR code) only into the runtime folder from `window/Runtime.js`: `$XDG_RUNTIME_DIR/miharchy`, made 0700 and checked at start to be the user's own real directory, as `plugin/Mark.js` and `window/miharchy` check it. `shell.qml` holds the config until that check ends. With no `XDG_RUNTIME_DIR`, or a failed check, `Runtime.folder()` is "" and those features write nothing: server images fail, the reading card says why, Setup gives the ID as text. No QML file reads `XDG_RUNTIME_DIR` itself (`tests/runtime.test.js`).
- A new overlay is one row in `window/Overlays.js`: its scope, editing name and hint. `shell.qml` passes its items to `Overlays.top`, and both the key path and the hint bar read the result (`root.overlay`). A text field that takes typed text is one entry in its `EDITORS` list.
- The mouse reaches the key commands and adds none: a click puts the view's cursor on an item (the state j/k set), a double click also sends `Commands.enter()` through `root.handleKey`. Hint lines are `HintBar.qml`: a part that starts with a key presses it (`Commands.hintParts`). A hint wider than its `maxWidth` wraps onto more lines, never under other text; the status bar caps it at the space beside the connection state and grows up to hold it. The reader's tap zones and wheel are `Reader.tapZone` and `Reader.wheel`. A panel over a view blocks the clicks outside it with a `MouseArea`, so a double click never sends Enter to the panel.
- Settings scrolls (`SettingsView.qml` is a Flickable that follows the cursor). A commit's error shows under its row; so does a row's `note` while the cursor is on it.
- `r` on a manga detail or in the reader that fails the same way again adds "Failed again at HH:MM:SS" to the notice, so a retry never looks like it did nothing. `Browse.reduceDetail` and `Reader.reduce` keep `retried` and `failedAt` through `Model.failure` and `Model.failedAt`; `Model.again` adds the line.
- Incognito mode is global meta `miharchy.incognito` (Settings row, palette `mode.incognito`). `Reader.open` takes it once, as Mihon's reader does; while on, `savePayload`, `trackPayload` and `deleteTarget` return null, so a read leaves no read state, no history (`lastReadAt` moves only with a save) and no tracker push. Explicit marks from a chapter list still apply. `Settings.modes()` names the modes on for the status bar.
- Downloaded only is global meta `miharchy.downloadedOnly` (Settings row, palette `mode.downloadedOnly`). As Mihon's, it forces the Downloaded filter on without saving over the stored choice (`Prefs.force`): the Library's `libraryFilterDownloaded` and the chapter list's `chapterFilterDownloaded`. The reader drops chapters not on disk whatever skip filtered says (`skip.downloaded` in `Chapters.readingOrder`), and Updates forces its `updatesFilterDownloaded` the same way. History and Browse stay whole, as in Mihon; the bar mark counts every unread update.
- Phone sync is a Settings action row (palette `sync.health`, "Show what the phone lacks"): sync health in one line, and Enter opens the sync panel in its health mode. `y` never applies a held sync from that mode (the key scope stays `sync`, and `SyncView.run` refuses), so a held sync the user kept stays held. The row and the panel word their age from `Date.now()` when health arrives, so it does not tick while Settings stays open. Details in `docs/agents/sync.md`.
- A peek (`GLOSSARY.md`) is the window on Hyprland's special workspace `miharchy`; Miharchy stores no peek state (Hyprland holds shown or hidden; the next key's order lives in window memory only). `window/miharchy peek` (the Setup peek key) reads the window's workspace from `hyprctl clients -j`: on `special:miharchy` it only toggles that workspace, so a hidden peek comes back as it was; on a normal one it calls IPC `peek` and focuses the window where it is, never moving it; with no window it starts one with `MIHARCHY_PEEK=1`, waits up to 3 s for its address, moves it there (`hl.dsp.window.move` with `window = "address:…"` and `follow = false`; Hyprland ignores an unknown key and moves the focused window) and shows it. The marker `$XDG_RUNTIME_DIR/miharchy/peek-starting` keeps a second press during those 3 s from starting another window. With no `XDG_RUNTIME_DIR`, or a `miharchy` folder there that is a symlink or not the user's own directory, the peek fails with an error; it never falls back to `/tmp`. `shell.qml` `peek()` sends `UpNext.payload()` (every library manga with its chapters, one request) and opens the head of `UpNext.list` through `openChapter`. The next key (`SUPER + CTRL + M`) runs `window/miharchy peek-next`, which always shows the peek: on `special:miharchy` it calls IPC `peekNext` and toggles the workspace only when no monitor shows it (`hyprctl monitors -j`, `specialWorkspace.name`); on a normal workspace it calls IPC `peekNext` and focuses; with no window it starts one with `MIHARCHY_PEEK=next`, as `peek` does. The popup's Up next rows run `window/miharchy peek-open <mangaId> <chapterId>`, which shows the peek as `peek-next` does, with IPC `peekOpen` or a cold start with `MIHARCHY_PEEK="<mangaId> <chapterId>"` (`Model.chapterTarget` tells it from `1` and `next`). `peekOpen` empties `upNextOrder`, so the next key starts a new run, and opens that chapter through `openChapter(target, true)`. `peek(true)` opens `UpNext.after(list, root.upNextOrder, <the reader's manga or null>)`: the manga after the reader's, the second with the reader closed, wrapping from the last to the head; a manga not in Up next gives the head, and an empty Up next the Library. Opening a chapter writes `lastReadAt`, so the opened manga leads a fresh `UpNext.list` and "the one after it" would only flip between two manga. So the window keeps `upNextOrder`, the manga ids of Up next at the first press of a run, in memory only, and `after` walks that order, skipping a manga that left Up next. A plain `peek`, a closed reader, or a reader on a manga outside that order starts a new run. Up next (`GLOSSARY.md`) takes each manga's next chapter as the Library's continue reading does (`Library.chapterPrefs`: the manga's chapter prefs and excluded scanlators, and Downloaded only) and sorts the manga in tiers: the next chapter partly read; started with at most `CLOSE_UNREAD` (5) unread after the filters; an unread update (fetched after `inLibraryAt`) in the last `FRESH_DAYS` (7). Tiers 1 and 2 go by newest `lastReadAt`, tier 3 by newest update. Each entry also carries its `tier`, `title`, `chapter` (the name) and what the popup's reason reads: `page` (`lastPageRead`), `pages` (`pageCount`, 0 for none), `unread` and `update` (seconds, 0 for none). It drops a manga with `source` null, and treats a manga hidden on History (`miharchy.historyHiddenAt`, `miharchy.historyClearedAt`) as not started, so only a fresh update brings it back. `tests/upnext.test.js` pins the rules, so Updates is behind it and shows a load error. With none, the Library opens with its search; a failed reply shows as the Library error instead. The peek tiles like Omarchy's scratchpad and hides on a workspace switch (Omarchy's `hide_special_on_workspace_change`); Esc keeps its meaning. A restart (`Q`) unsets `MIHARCHY_PEEK` and comes back as a normal window.
- Catch-up (`GLOSSARY.md`) is the Settings row `catchUp` (global meta `miharchy.catchUp`, "0" off, default "3"). Both `peek()` paths, the plain one and the next key's, and `peekOpen` open their chapter through `openChapter(target, true)`, which passes `peek` through `UpdatesView.openChapter` and `read` to `ReaderView.start` and `Reader.open`; every other way into the reader passes nothing, so it never stops. `Reader.open` is fresh state, so each peek open starts the count at 0. The reader counts `finished`, the chapters it reads on past (`Reader.onward`: a forward move out of a chapter whose pages loaded), so `]` and a failed chapter do not count and Incognito does. Each turn carries the setting (`catchUp` in the turn event, as `always`), and the forward turn past the end that would make `finished + 1` reach it shows the transition page whatever `alwaysShowChapterTransition` says, with `transition.caughtUp` (`Reader.caughtUp`). A turn on there stays; a turn back leaves it, and reading on again stops again. When it shows, `ReaderView` signals `caughtUpOn` and `shell.qml` `lookUpNext` sends `UpNext.payload()` and picks the manga the next key would, through the same `nextInOrder` (`UpNext.after` over `upNextOrder`, starting the order when the manga is not in it), with its title from the library; the manga itself, alone in Up next, or a failed reply is none. `transitionLines(t, title)` says "Caught up on N chapters" and the title, "Looking up Up next" until the reply, or "Nothing else is up next". `c` (`reader.catchUpContinue`) sets `lifted` and reads on: no more stops in this reader. `n` (`reader.catchUpNext`) runs the next key itself (`peek(true)`), so the stop's pick, the order and the count reset live in one place. Both do nothing off the stop; a `HintBar` on the page shows them. Hiding and showing the peek leaves the reader as it is, so the count holds.
- A view's sort, filter and display choices go through `window/Prefs.js`: the view lists them as a table of `{ key, default, options }`, and Prefs loads, validates and saves them as global meta `miharchy.<key>`. `window/PrefStore.qml` holds one table's values and sends its saves one at a time; a view gives it the table (and a `mangaId` for one manga's choices). The Library's table is `Library.PREFS`; its search does not persist, as in Mihon.
- A list of covers takes its rows through `window/RowModel.qml`, never an array as its model: a new array rebuilds every cell, jumps to the top, and Qt may decode each cover again, blank for a moment (#219). RowModel is a ListModel that `Model.listChanges` changes in place (remove, insert, move, set, keyed by id or a key you give), or resets when most rows move; a delegate still reads `modelData`. The Library, its list, History, Updates and Global search use it; the Browse source grid keeps its own append-only `Browse.gridChanges`. The Library's cursor follows its manga (`Model.follow`), and a new category starts at the top.
- A preference for one manga lives in its manga meta under the same prefix (`setMangaMeta`). The chapter list's filter and sort (`Chapters.PREFS`, Mihon's `chapterFlags`) are per manga: the manga's own meta wins over global meta, which is the default for every manga. The reader gets the chapters in the manga's chosen sort, read ascending, like Mihon (`Chapters.readingOrder`). The reader settings skip read, skip filtered (on by default, as in Mihon) and skip duplicates (`miharchy.skipRead`, `skipFiltered`, `skipDupe`) drop chapters from that list as it opens, and again at once when one changes, never the chapter open. Excluded scanlators (Mihon's `excluded_scanlators`) are manga meta `miharchy.excludedScanlators`, a JSON list, in their own table `Chapters.SCANLATOR_PREFS`, never in `Chapters.PREFS`: "save as default" must not copy or reset them. Their chapters leave the chapter list and the reader's list whatever the skip settings, as Mihon's `applyScanlatorFilter`. `ReaderView.start` builds the list for every caller: it opens on the default chapter choices and reorders once the manga's meta loads. The reading mode `m` picks is `miharchy.readingMode`. It wins over a long strip detected from genre tags or a Webtoons source (`Browse.longStrip`), which wins over the default reading mode setting.
- `s` in the reader opens its settings panel (Mihon's reader settings sheet): the manga's reading mode, then the Settings rows in `Reader.PANEL_KEYS`. The panel shows and saves those same rows; it holds no setting of its own. A new reader setting is a `Settings.ROWS` entry plus its key in `PANEL_KEYS`.
- Crop borders (`GLOSSARY.md`) is the Settings and panel rows `cropBordersPaged` (default on) and `cropBordersWebtoon` (default off, also continuous vertical); `ReaderView.cropping` is the row of the mode shown. A page's `ServerImage` writes its file as usual, and `hold` keeps its `source` empty until the analysis is in (`ServerImage` applies it a tick later, so `sourceSize` and `sourceClipRect` are set first): a crop never jumps. The analysis: one `Canvas` (`scanner`, `opacity: 0`; an invisible Canvas never becomes available) loads the file apart from the Image, draws it at 256 px on its long side, and hands `getImageData` to `Scan.analyze`, which returns the box for paged, the strip (left and right) and each half of a wide page, in fractions of the page, null for whole. The rules live there and in `tests/scan.test.js`: a near-white or near-black margin, a line of it may hold 5% other pixels, at most 25% from a side, none when the box keeps less than 60% of the area. `reader.scans` holds each result by URL with its `ms`, or `{ failed }`, which shows the page whole; a file the Canvas never answers for fails after 5 s. The six pager slots and the strip's `cacheBuffer` are what the reader preloads, so those pages are analyzed ahead. `Reader.place` turns a box into the decode size and the clip in decoded pixels (`sourceClipRect` is relative to the `sourceSize`-scaled image, and an Image's implicit size is its clip's, so `pageSizes` takes the scan's natural size, never a clipped implicit size). A split page shows its half through the same clip: split first, then the half's own box, then pairing. `S` and `Y` read `filePath`, the original file.
- Auto levels (`GLOSSARY.md`) is the Settings and panel row `autoLevels` (default on, every mode); `ReaderView.leveling` is it, and the analysis runs (and `hold` waits) while `scanning`, crop or levels. The same `Scan.analyze` pass returns `levels: { page, strip, halves }`: for each box (the crop box, with Crop borders off too, else the whole page or half) a luminance histogram gives one black and one white point for all three channels, clipping at most 0.5% at each end. A part whose points are more than 204 apart is left as it is (already full range), and so is one closer than 64 (a blank or flat page, where a stretch shows only grain); `tests/scan.test.js` pins the rules. `Reader.spread` puts each item's `levels` (`levelsAt`, split and pairing as `region`), the strip reads `levels.strip`. `Scan.effect` turns the points into `MultiEffect`'s `contrast` and `brightness`: its shader draws `(v - 0.5) * (1 + contrast) + 0.5 + brightness`, a linear stretch, and Qt 6.11 does not clamp `contrast` to its documented -1..1. The page's `ServerImage` takes it as `layer.effect`, `layer.enabled` only while it has levels, so a full-range page costs nothing; a leveled page costs one RGBA texture at its shown size (a fit-screen page on a 1280x800 window about 1.7 MB, at zoom 4 about 27 MB) and one more draw. No shader is built or committed. Only the RHI renderer runs `MultiEffect`: an offscreen drive needs `QT_QUICK_BACKEND=rhi` in front of `drive.sh`, or the software renderer draws no stretch.
- Original pages (`GLOSSARY.md`): `O` (`reader.original`) flips `ReaderView.original`, which `start()` sets back to false and nothing saves. It is the one gate for every page cleanup: `cropping` and `leveling` are false while it is on, so no page is analyzed, clipped or stretched, and `scans` stays, so `O` again crops and levels at once. The bottom-left line adds "original page".
- `a` in the reader starts or stops auto-scroll (`reader.autoScroll`, not in Mihon). One `Timer` in `ReaderView.qml` runs `Reader.autoPlan`: in the strip it moves `contentY` a little every 16 ms, and `track()` saves the read state as for any scroll; paged, it runs the path Space takes (`act`). It starts at the Settings and panel row `autoScrollSpeed` (0.5x to 3x, `Reader.AUTO_SPEEDS` reads its options); while it runs `+`/`-` step the speed and save it. Any other command, a click, a drag or the wheel stops it, and so do the strip's end and the transition page. Its turns always show the transition page, so it never opens the next chapter by itself.
- Settings shows the disk space of downloads and of core's image cache from `storage.get` (`Storage.SIZES_PAYLOAD`): core measures its own folders, the cache being the covers of manga outside the library. "Clear the cache" sends `cache.clear`, which answers `{ freed }`.
