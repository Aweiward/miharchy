# Window

Conventions that hold across the views in `window/`: restart, mouse, Settings, modes, preferences, the reader's chapter list.

- The window never reloads its code in place (`settings.watchFiles: false` in `shell.qml`): Quickshell's reload would catch an update half written and drop the reader without its save. Every 30 s it fingerprints its own `*.qml` and `*.js` (`window/Restart.js`, read only); when the files differ from what it loaded, the status bar shows "new version   Q restart". `Q` (`window.restart`, also the palette and a click) starts a detached sh that waits for this pid to end, unsets `MIHARCHY_OPEN_CHAPTER` and `MIHARCHY_OPEN_VIEW`, and runs the launcher, then runs the quit path (`reader.quit()`).
- The mouse reaches the key commands and adds none: a click puts the view's cursor on an item (the state j/k set), a double click also sends `Commands.enter()` through `root.handleKey`. Hint lines are `HintBar.qml`: a part that starts with a key presses it (`Commands.hintParts`). A hint wider than its `maxWidth` wraps onto more lines, never under other text; the status bar caps it at the space beside the connection state and grows up to hold it. The reader's tap zones and wheel are `Reader.tapZone` and `Reader.wheel`. A panel over a view blocks the clicks outside it with a `MouseArea`, so a double click never sends Enter to the panel.
- Settings scrolls (`SettingsView.qml` is a Flickable that follows the cursor). A commit's error shows under its row; so does a row's `note` while the cursor is on it.
- `r` on a manga detail or in the reader that fails the same way again adds "Failed again at HH:MM:SS" to the notice, so a retry never looks like it did nothing. `Browse.reduceDetail` and `Reader.reduce` keep `retried` and `failedAt` through `Model.failure` and `Model.failedAt`; `Model.again` adds the line.
- Incognito mode is global meta `miharchy.incognito` (Settings row, palette `mode.incognito`). `Reader.open` takes it once, as Mihon's reader does; while on, `savePayload`, `trackPayload` and `deleteTarget` return null, so a read leaves no read state, no history (`lastReadAt` moves only with a save) and no tracker push. Explicit marks from a chapter list still apply. `Settings.modes()` names the modes on for the status bar.
- Downloaded only is global meta `miharchy.downloadedOnly` (Settings row, palette `mode.downloadedOnly`). As Mihon's, it forces the Downloaded filter on without saving over the stored choice (`Prefs.force`): the Library's `libraryFilterDownloaded` and the chapter list's `chapterFilterDownloaded`. The reader drops chapters not on disk whatever skip filtered says (`skip.downloaded` in `Chapters.readingOrder`), and Updates forces its `updatesFilterDownloaded` the same way. History and Browse stay whole, as in Mihon; the bar mark counts every unread update.
- Phone sync is a Settings action row (palette `sync.health`, "Show what the phone lacks"): sync health in one line, and Enter opens the sync panel in its health mode. `y` never applies a held sync from that mode (the key scope stays `sync`, and `SyncView.run` refuses), so a held sync the user kept stays held. The row and the panel word their age from `Date.now()` when health arrives, so it does not tick while Settings stays open. Details in `docs/agents/sync.md`.
- A peek (`GLOSSARY.md`) is the window on Hyprland's special workspace `miharchy`; Miharchy stores no peek state (Hyprland holds shown or hidden; the next key's order lives in window memory only). `window/miharchy peek` (the Setup peek key) reads the window's workspace from `hyprctl clients -j`: on `special:miharchy` it only toggles that workspace, so a hidden peek comes back as it was; on a normal one it calls IPC `peek` and focuses the window where it is, never moving it; with no window it starts one with `MIHARCHY_PEEK=1`, waits up to 3 s for its address, moves it there (`hl.dsp.window.move` with `window = "address:…"` and `follow = false`; Hyprland ignores an unknown key and moves the focused window) and shows it. The marker `$XDG_RUNTIME_DIR/miharchy/peek-starting` keeps a second press during those 3 s from starting another window. `shell.qml` `peek()` sends `UpNext.payload()` (every library manga with its chapters, one request) and opens the head of `UpNext.list` through `openChapter`. The next key (`SUPER + CTRL + M`) runs `window/miharchy peek-next`, which always shows the peek: on `special:miharchy` it calls IPC `peekNext` and toggles the workspace only when no monitor shows it (`hyprctl monitors -j`, `specialWorkspace.name`); on a normal workspace it calls IPC `peekNext` and focuses; with no window it starts one with `MIHARCHY_PEEK=next`, as `peek` does. The popup's Up next rows run `window/miharchy peek-open <mangaId> <chapterId>`, which shows the peek as `peek-next` does, with IPC `peekOpen` or a cold start with `MIHARCHY_PEEK="<mangaId> <chapterId>"` (`Model.chapterTarget` tells it from `1` and `next`). `peekOpen` empties `upNextOrder`, so the next key starts a new run, and opens that chapter through `openChapter(target, true)`. `peek(true)` opens `UpNext.after(list, root.upNextOrder, <the reader's manga or null>)`: the manga after the reader's, the second with the reader closed, wrapping from the last to the head; a manga not in Up next gives the head, and an empty Up next the Library. Opening a chapter writes `lastReadAt`, so the opened manga leads a fresh `UpNext.list` and "the one after it" would only flip between two manga. So the window keeps `upNextOrder`, the manga ids of Up next at the first press of a run, in memory only, and `after` walks that order, skipping a manga that left Up next. A plain `peek`, a closed reader, or a reader on a manga outside that order starts a new run. Up next (`GLOSSARY.md`) takes each manga's next chapter as the Library's continue reading does (`Library.chapterPrefs`: the manga's chapter prefs and excluded scanlators, and Downloaded only) and sorts the manga in tiers: the next chapter partly read; started with at most `CLOSE_UNREAD` (5) unread after the filters; an unread update (fetched after `inLibraryAt`) in the last `FRESH_DAYS` (7). Tiers 1 and 2 go by newest `lastReadAt`, tier 3 by newest update. Each entry also carries its `tier`, `title`, `chapter` (the name) and what the popup's reason reads: `page` (`lastPageRead`), `pages` (`pageCount`, 0 for none), `unread` and `update` (seconds, 0 for none). It drops a manga with `source` null, and treats a manga hidden on History (`miharchy.historyHiddenAt`, `miharchy.historyClearedAt`) as not started, so only a fresh update brings it back. `tests/upnext.test.js` pins the rules, so Updates is behind it and shows a load error. With none, the Library opens with its search; a failed reply shows as the Library error instead. The peek tiles like Omarchy's scratchpad and hides on a workspace switch (Omarchy's `hide_special_on_workspace_change`); Esc keeps its meaning. A restart (`Q`) unsets `MIHARCHY_PEEK` and comes back as a normal window.
- Catch-up (`GLOSSARY.md`) is the Settings row `catchUp` (global meta `miharchy.catchUp`, "0" off, default "3"). Both `peek()` paths, the plain one and the next key's, and `peekOpen` open their chapter through `openChapter(target, true)`, which passes `peek` through `UpdatesView.openChapter` and `read` to `ReaderView.start` and `Reader.open`; every other way into the reader passes nothing, so it never stops. `Reader.open` is fresh state, so each peek open starts the count at 0. The reader counts `finished`, the chapters it reads on past (`Reader.onward`: a forward move out of a chapter whose pages loaded), so `]` and a failed chapter do not count and Incognito does. Each turn carries the setting (`catchUp` in the turn event, as `always`), and the forward turn past the end that would make `finished + 1` reach it shows the transition page whatever `alwaysShowChapterTransition` says, with `transition.caughtUp` (`Reader.caughtUp`). A turn on there stays; a turn back leaves it, and reading on again stops again. When it shows, `ReaderView` signals `caughtUpOn` and `shell.qml` `lookUpNext` sends `UpNext.payload()` and picks the manga the next key would, through the same `nextInOrder` (`UpNext.after` over `upNextOrder`, starting the order when the manga is not in it), with its title from the library; the manga itself, alone in Up next, or a failed reply is none. `transitionLines(t, title)` says "Caught up on N chapters" and the title, "Looking up Up next" until the reply, or "Nothing else is up next". `c` (`reader.catchUpContinue`) sets `lifted` and reads on: no more stops in this reader. `n` (`reader.catchUpNext`) runs the next key itself (`peek(true)`), so the stop's pick, the order and the count reset live in one place. Both do nothing off the stop; a `HintBar` on the page shows them. Hiding and showing the peek leaves the reader as it is, so the count holds.
- A view's sort, filter and display choices go through `window/Prefs.js`: the view lists them as a table of `{ key, default, options }`, and Prefs loads, validates and saves them as global meta `miharchy.<key>`. `window/PrefStore.qml` holds one table's values and sends its saves one at a time; a view gives it the table (and a `mangaId` for one manga's choices). The Library's table is `Library.PREFS`; its search does not persist, as in Mihon.
- A list of covers takes its rows through `window/RowModel.qml`, never an array as its model: a new array rebuilds every cell, jumps to the top, and Qt may decode each cover again, blank for a moment (#219). RowModel is a ListModel that `Model.listChanges` changes in place (remove, insert, move, set, keyed by id or a key you give), or resets when most rows move; a delegate still reads `modelData`. The Library, its list, History, Updates and Global search use it; the Browse source grid keeps its own append-only `Browse.gridChanges`. The Library's cursor follows its manga (`Model.follow`), and a new category starts at the top.
- A preference for one manga lives in its manga meta under the same prefix (`setMangaMeta`). The chapter list's filter and sort (`Chapters.PREFS`, Mihon's `chapterFlags`) are per manga: the manga's own meta wins over global meta, which is the default for every manga. The reader gets the chapters in the manga's chosen sort, read ascending, like Mihon (`Chapters.readingOrder`). The reader settings skip read, skip filtered (on by default, as in Mihon) and skip duplicates (`miharchy.skipRead`, `skipFiltered`, `skipDupe`) drop chapters from that list as it opens, and again at once when one changes, never the chapter open. Excluded scanlators (Mihon's `excluded_scanlators`) are manga meta `miharchy.excludedScanlators`, a JSON list, in their own table `Chapters.SCANLATOR_PREFS`, never in `Chapters.PREFS`: "save as default" must not copy or reset them. Their chapters leave the chapter list and the reader's list whatever the skip settings, as Mihon's `applyScanlatorFilter`. `ReaderView.start` builds the list for every caller: it opens on the default chapter choices and reorders once the manga's meta loads. The reading mode `m` picks is `miharchy.readingMode`. It wins over a long strip detected from genre tags or a Webtoons source (`Browse.longStrip`), which wins over the default reading mode setting.
- `s` in the reader opens its settings panel (Mihon's reader settings sheet): the manga's reading mode, then the Settings rows in `Reader.PANEL_KEYS`. The panel shows and saves those same rows; it holds no setting of its own. A new reader setting is a `Settings.ROWS` entry plus its key in `PANEL_KEYS`.
- Crop borders (`GLOSSARY.md`) is the Settings and panel rows `cropBordersPaged` (default on) and `cropBordersWebtoon` (default off, also continuous vertical); `ReaderView.cropping` is the row of the mode shown. A page's `ServerImage` writes its file as usual, and `hold` keeps its `source` empty until the analysis is in (`ServerImage` applies it a tick later, so `sourceSize` and `sourceClipRect` are set first): a crop never jumps. The analysis: one `Canvas` (`scanner`, `opacity: 0`; an invisible Canvas never becomes available) loads the file apart from the Image, draws it at 256 px on its long side, and hands `getImageData` to `Scan.analyze`, which returns the box for paged, the strip (left and right) and each half of a wide page, in fractions of the page, null for whole. The rules live there and in `tests/scan.test.js`: a near-white or near-black margin, a line of it may hold 5% other pixels, at most 25% from a side, none when the box keeps less than 60% of the area. `reader.scans` holds each result by URL with its `ms`, or `{ failed }`, which shows the page whole; a file the Canvas never answers for fails after 5 s. The six pager slots and the strip's `cacheBuffer` are what the reader preloads, so those pages are analyzed ahead. `Reader.place` turns a box into the decode size and the clip in decoded pixels (`sourceClipRect` is relative to the `sourceSize`-scaled image, and an Image's implicit size is its clip's, so `pageSizes` takes the scan's natural size, never a clipped implicit size). A split page shows its half through the same clip: split first, then the half's own box, then pairing. `S` and `Y` read `filePath`, the original file. Auto levels (#281) reads the same pass: `Scan.luminance`.
- Original pages (`GLOSSARY.md`): `O` (`reader.original`) flips `ReaderView.original`, which `start()` sets back to false and nothing saves. It is the one gate for every page cleanup: `cropping` is false while it is on, so no page is analyzed and none is clipped, and `scans` stays, so `O` again crops at once. Auto levels (#281) checks the same property. The bottom-left line adds "original page".
- `a` in the reader starts or stops auto-scroll (`reader.autoScroll`, not in Mihon). One `Timer` in `ReaderView.qml` runs `Reader.autoPlan`: in the strip it moves `contentY` a little every 16 ms, and `track()` saves the read state as for any scroll; paged, it runs the path Space takes (`act`). It starts at the Settings and panel row `autoScrollSpeed` (0.5x to 3x, `Reader.AUTO_SPEEDS` reads its options); while it runs `+`/`-` step the speed and save it. Any other command, a click, a drag or the wheel stops it, and so do the strip's end and the transition page. Its turns always show the transition page, so it never opens the next chapter by itself.
- Settings shows the disk space of downloads and of the server's image cache (`window/Storage.js`). Suwayomi has no API for it, so the window runs `du` on the server's folders: downloads are `downloadsPath`, or `<root>/downloads` when it is blank (the library's covers live there too); the cache is `<java.io.tmpdir>/Tachidesk/manga-cache` and `thumbnails`, `/tmp` for the JVM by default and shared with any other Suwayomi on the machine. The root is `~/.local/share/miharchy/suwayomi`, as in `server/miharchy-server`. A test run sets `MIHARCHY_SERVER_ROOT` and `MIHARCHY_SERVER_TMPDIR` to its scratch server's `rootDir` and `java.io.tmpdir`, so it never measures the real ones. "Clear the cache" sends `clearCachedImages` with `cachedPages` and `cachedThumbnails` only, never `downloadedThumbnails`, and reports the space the cache lost.
